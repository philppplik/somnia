# CV: explicit open-text folder source selection

Replaces the flat source checklist in LocalSearchPanel with exact-parent folder groups, selected/total count, UTF-8 text totals, select/deselect-folder actions and individual exceptions. Root, nested folders and similarly named prefixes remain separate. This is selection among already-open eligible .txt/.md sources, not a filesystem folder grant/import/crawl. No new source read, no closed/hidden/binary/config file expansion. Invalid/traversal/windows path scope is refused, not silently regrouped.

Folder selection is whole-group: validate exact current membership and selected IDs, then existing raw/normalized source limits (32 sources,256KiB,256 chunks); overflow refuses the complete change with notice, preserves previous selection. Empty deselection is permitted. Individual exceptions retain existing per-file behavior; oversize scope cannot build. Selection change closes/cancels the old session, removes results/citation context and requires fresh exact-text consent; no automatic rebuild. Source/model binding and editor citation jump remain unchanged. All5 locales, shared DS controls, no new dependencies/budget changes/persistence/cloud/answers/writes/download/inference, $0.

Validation: folder grouping/union/exceptions/subfolder/path/overflow unit tests; new390px light/dark browser flow selects group with exception, adds nested group, reviews/builds/searches, then deselects group and verifies old ready/results/consent are gone. Separate33-file group refusal test asserts no selection or transport. Existing CU batching and CI phrase browser regressions retained. Synthetic sources/adapters only; production host is code-wired, actual daemon/native full-app remains CI/manual gate. No claim of filesystem import or real embedding quality.

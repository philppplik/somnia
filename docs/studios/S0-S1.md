# Studios: Code shell foundation (S0 + first pill, rebased onto d91046f)

Only Code is a runtime-ready Studio in this change. Photo, Designer, Documents and Video are not registered, not advertised and have no placeholder pills. Their engines and migrations are separate phases.

## Manifest and adapters

`phase1/src/lib/studios/registry.ts` defines formats, fixed rails, header menus and views, bottom-bar presets and slots, inspector registry, tools, commands, shortcuts, canvas host, agent contributions and a context adapter hook. `code.ts` declares today's workspace. `components/studios/hosts.tsx` maps the Code canvas and inspector identifiers to the existing components. Global Agent, chat, account, Settings, Extensions and document/history service remain outside those hosts.

`activeStudio` and `studioByTab` live in appStore. `requestStudio` changes shell state only. It does not save, export, convert, commit a tool, touch undo or close the global Agent. Explicit manual requests beat automatic requests. Pending-tool requests return `pending-tool` without changing shell; the caller must present its tool-specific Apply/Discard decision, then request again. No pending-tool UI is invented for Code, since there is no second runtime-ready host to switch to.

The rebased revision d91046f does not contain `deriveContext`, `contextRegistry` or `AppDialogs`. The generic `deriveContext` adapter deliberately returns its input unchanged. When the context-ui wave lands, pass its computed UiContext through this adapter and map `code.inspector` to the real section registry. Do not fork context rules inside Studios.

## Pill and View menu

The centered header control is now the Studio radiogroup. Only the active Studio has a visible label. Named radio buttons have roving focus, arrow/Home/End support and a polite announcement. There is no new animation, so reduced-motion users get no shell or thumb transition.

The first View menu group is a checked radio group, with the active mode in a single status-bar context slot. Code uses Visual/Split/Code; Markdown labels remain Preview/Split/Source. Remaining commands retain their order, including disabled service commands. View commands stay discoverable in the command palette.

Shortcut migration:

- Ctrl+1 (Cmd+1 on macOS): Code Studio.
- Ctrl+Alt+1: Visual / Markdown Preview.
- Ctrl+Alt+2: Split.
- Ctrl+Alt+3: Code / Markdown Source.
- Ctrl+2..5 are not installed while the corresponding Studios do not exist.

User overrides are preserved, not silently rewritten. Existing Settings > Shortcuts shows collisions. The global dispatcher fails closed on an ambiguous chord and gives a translated notice instead of executing the first matching command. Save/Undo/Redo/Open bindings do not change.

## Proof and tests

S0 retains the original `code-*` snapshots from 5c1199c unchanged as historical evidence. They no longer describe the current shell: d91046f removed the Assets rail icon as part of the Components redesign. This shifts the Components/CSS/Versions icons upward. Do not restore Assets just to satisfy those older images.

Four separate `current-code-*` snapshots were captured on the unmodified d91046f shell (empty, web, Markdown and code-only). The rebased S0 matches all four with `maxDiffPixels: 0`. This proves that the declarative refactor itself introduces no perceptible shell change against its actual base. S1 uses separate `studio-code-*` snapshots for its intentional Header pill and status-slot changes. The View menu is covered by the Studio E2E screenshot and checked radio assertions. Only these new/current references were generated; the old `code-*` PNG bytes remain unchanged.

The inline raster provider, raster/PDF side panels, SVG canvas, media close guards, Components drag hint and left-tab sanitization remain from d91046f. The Studio host wraps the existing Canvas/Inspector rather than reimplementing their context routing. The view-mode status slot is hidden while binary media is active, so it does not mislabel the raster/PDF editor. No new Photo/Designer/Document Studio is advertised.

Validation on Linux: `tsc -b`, production Vite build after the real Rust 1.95/wasm-bindgen 0.2.129 PhotoCraft build, full core suite (1543 passed, 18 skipped, 26 todo, zero failures), Studio/Shell/Markdown/Canvas E2E with one worker, and Components/raster/SVG/PDF E2E. Screenshots were visually inspected for empty/web/Markdown/code-only shells, the View menu, Components, raster, SVG and PDF inline panels. An initial concurrent core/E2E run lost its Vite server; isolated one-worker reruns passed. Native save dialogs and platform window behaviour still require desktop testing.

`studios.test.ts` covers registry readiness, preserved context identity, fixed rail order, manual precedence, tab memory, pending-tool refusal and unchanged document/global state. `studios.spec.ts` covers the actual radio semantics, arrows, View group, status context, keyboard/palette routes, collision refusal, reduced motion, and all five locales. Existing UI tests use the View menu or migrated view chords rather than removed header buttons.

## Remaining phases

Full compatible/incompatible-format routing, per-tab persistence across restart, per-Studio layout memory, Settings controls, tab format suggestions, external Studio registration and global slot enforcement require real second Studios. These are not claimed as implemented. The Photo/Designer/Docs/Video host adapters and tool-specific pending guards must be supplied before registering those Studios.

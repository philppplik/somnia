# Somnia v11.1.0 - Release notes draft

Status: released as v11.1.0 from the commit with green CI. The installers are unsigned and
Windows/macOS desktop acceptance by the maintainer is still outstanding (see Known issues).

## Highlights

### Collaboration identity and easier chat access

Join starts with the name from your local profile. If the profile is empty, the
name is saved only after a successful join and only if the profile is still
empty. Changing a session name does not overwrite an existing profile. Hosts use
their profile name, or Host when none is set; an over-long profile name requires
a valid session name in the hosting dialog.

A local profile picture is converted to a session-only 48 x 48 JPEG thumbnail
(maximum 8 KiB) for chat and the mention picker. The original image is not shared.
Missing, rejected or failed thumbnails fall back to initials. Mentions retain
participant IDs, so people with the same display name stay distinct. Names and
pictures are not verified identity.

The Chat button now sits above Agent in the right rail during a collaboration
session. Its unread badge displays `9+` above nine unread messages. Use
**Ctrl+Alt+C** on Windows/Linux or **Cmd+Alt+C** on macOS to open chat or close its
panel when chat is already visible. The Agent button switches back to Agent;
ending the session also returns to Agent. The status-bar chat opener is removed.

Session chat, already included in beta.5, supports plain-text messages, one-level
replies, ID-based mentions, attachments and explicit code-location jumps. It uses
the existing encrypted collaboration link and a separate volatile store: chat
is not saved with the project, added to recovery/export or sent to AI. Code
participant badges can show activity, remain visible or be hidden via Settings >
Collaboration.

Technical detail: [session chat and participant badges](../../phase1/notes/session-chat-badges.md).
That earlier note records beta.5 behavior, including its original chat shortcut;
the rail toggle above is the new beta.6 entry point.

### Glass v2 and corner controls

Settings > Appearance adds an opacity slider from 0 to 100%, CSS blur from 0 to
40 px, and separate Window frame, Panels and Code editor scopes. Defaults keep
the previous look: 68% frame opacity, 88% panels and 24 px CSS blur. Code editor
glass is off by default; text, caret and selection stay opaque when it is enabled.

Below 60% opacity, the code scope offers a low-contrast warning with "Set to 60%"
and "Keep anyway". Below 55%, measurable color combinations under 4.5:1 against
a neutral grey reference are raised to 55% for the code surface. This is a
reference-based safeguard, not a contrast guarantee over every desktop image.
Reduced-transparency preferences make the scopes opaque and remove CSS blur.

The beta.5 outer-radius setting remains available from 0 to 25 px for the frame
and workspace cards, including the communication panel. Dialogs and controls
keep their own radius tokens. Existing stored appearance choices are migrated
with defaults for the new keys.

Technical detail: [Glass v2](../GLASS.md) and
[appearance surfaces](../design/appearance-surfaces.md). The Glass v2 note
supersedes the earlier note's description of opaque code surfaces.

### LaTeX stage 1

Markdown preview renders inline and display math with KaTeX using `$...$`,
`$$...$$`, `\(...\)` and `\[...\]`. Code spans/fences, escaped dollar signs and
price-like text remain text. KaTeX and its fonts load only when needed. The
Markdown math setting can disable formula rendering.

`.tex` files get syntax highlighting and a limited preview of text, sections,
lists, supported text styles and equation/align/gather blocks. This is a preview,
not a LaTeX compiler. Unsupported commands are listed rather than silently
promised as supported. Formula errors appear in Problems, the editor gutter and
the status bar; loading and failure states offer notices and retry.

KaTeX trust is always denied. Commands such as `\href`, `\url`,
`\includegraphics` and `\htmlClass` are reported as disabled for security.
Expansion and size limits are set. `.tex` commands such as `\input`, `\include`
and `\write` are never executed. Formula markup is filled into Markdown text
positions only, not link titles, image attributes or other HTML attributes.

Technical detail: [LaTeX stage 1](../../phase1/notes/latex-stufe1.md).

### Markdown live preview

Markdown files now use Source, Split and Preview views with Markdown syntax
highlighting. The source toolbar provides bold, italic, links, inline code,
bullet lists and task lists; More includes headings, numbered lists, quotes,
fenced code blocks, tables and strikethrough. Link and code-block dialogs insert
on confirmation. **Ctrl/Cmd+B** and **Ctrl/Cmd+I** format in the Markdown editor;
Enter continues lists and Shift+Enter inserts a plain newline.

The read-only preview includes tables, disabled task checkboxes, footnotes and
heading anchors. Split view can sync scrolling in either direction using mapped
source blocks. Reveal in source selects the corresponding source block. Relative
Markdown links open files already in the project, and fragment links scroll to
anchors. Raw HTML is disabled, unsafe URL schemes are rejected and images render
only through the local media resolver, without remote image requests.

### Save and close dialogs

Already included in beta.5, Save, window-close and Close Project use the same
Export-style dialog shell, file card, clear footer actions and narrow-width
layout. The new-folder hint uses the actual folder-name calculation. Closing
with unsaved changes retains explicit save/keep, discard and cancel choices;
this is a presentation update, not removal of the data-loss safeguards.

## Fixes

- Chat and Agent share the outer-radius styling in the communication panel.
- The dedicated rail button replaces the duplicate status-bar chat opener.
- KaTeX rendering is integrated with the Markdown renderer while retaining
  source-line maps, formula counts, diagnostics and security blocks.

## Known issues

- LaTeX stage 1 has no PDF compilation, package support, BibTeX or `\label`/`\ref`.
  `align` receives one equation number per block. A failed lazy-loaded chunk may
  require reloading Somnia if the browser refuses the retry.
- Markdown preview is not a visual document editor. Rendered tasks cannot be
  toggled there. Scroll sync is block-based, not a pixel-perfect source/preview
  match. Remote images are deliberately not loaded; mail links currently show
  an unsupported-link notice.
- Glass requires successful Windows Acrylic/macOS Vibrancy activation. Linux,
  web, high contrast and native activation failures stay solid. CSS blur does
  not replace the OS-controlled desktop effect; radius does not change an
  OS-enforced window mask. Non-hex colors cannot be measured for the code floor
  and still receive the low-opacity warning.
- Chat has no permanent archive. Limits include 8 KiB UTF-8 text per message,
  500 visible messages, 512 KiB visible history, 10 MB per attachment and 50 MB
  across a session. Extremely long sessions can outgrow the CRDT snapshot cap
  and need a fresh session. Generic files and PDFs are download-only, not scanned
  for malware or automatically opened. Downloaded copies cannot be erased when
  a session ends.
- Chat sharing confirmation is not proof of delivery to every participant or
  verified authorship. Link-key holders can forge participant data. Code-location
  jumps use file/line fallback; no shared Canvas cursor or follow mode is added.
- Windows/WebView2, real native drag/drop, high-DPI crowded cursors, native glass
  and two-PC LAN/firewall behavior need desktop acceptance. Source tests and
  synthetic/browser tests are not evidence that those checks passed.

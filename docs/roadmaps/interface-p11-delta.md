# Interface P11 delta: component swap and variant property axes

Rebased on fetched `int/beta5` `7c13b003` with integrated P9/P10 preserved. Explicit P11 scope, no new dependency, native format, app E2E or production claim.

- Instance component swap replaces the component reference in one undoable transaction. Root position, size overrides and matching component slots keep their descendant IDs and overrides; slots missing from the new variant stay preserved as the existing visible orphan warnings and are never applied to another layer. When the target component defines property axes, the swap prefers the variant whose values match the current instance on shared axes, falling back to the first variant. Same/missing component and locked instances reject without changing the session; a swap that would create a component-reference cycle fails validation and rolls back.
- Variant property axes can be renamed and removed on local components. Rename updates the definition and every variant value atomically, keeping instance property selections valid. Removal first proves the remaining axes still distinguish every variant; an ambiguous removal that would merge variants rejects before any mutation. Removing the last axis clears property definitions and per-variant values. Both operations are undoable and round-trip through snapshots and recovery.
- Existing v1 semantics are unchanged: slot-based text/fill/hidden/name/geometry overrides, explicit detach and reset, master edit plus propagation in one transaction, and override validation through the closed key list. No typed axes beyond string enums yet; text/boolean/swap property types from the concept remain future work.
- UI reuses shared controls: instance section gains a Component select with a visible warning-preservation note; master property blocks gain rename fields and remove buttons. Five-locale labels added as a catalogue merge; no token/global CSS or budget change. Twelfth app acceptance case added (CI-only); actual app E2E remains unrun locally.

# Local model management phase C

2026-10-14. Existing explicit pull review, per-layer progress, verified completion, cancellation and digest-pinned delete remain. This slice adds a native folder picker for the actual Ollama models directory, fs2 available-space read and an opaque session token. No arbitrary path comes from renderer. The selected volume is user-declared, NOT daemon-verified storage; app-data and process environment are not assumed to identify daemon storage.

Before pull, review shows free bytes and a known catalog estimate +25% +1 GiB reserve. Unknown model tags keep exact size unknown and require acknowledgment. Known insufficient or expired checks cannot confirm. Capacity is refreshed before transport and again natively at pull start. Native pull now requires the selected-folder token. No auto pull or auto folder discovery. Free capacity can still change, shared blobs/caches make exact required bytes unknown, and a wrong user-selected volume invalidates fit; no installation guarantee. Selected path/token is session-only, never a telemetry/log value. Native filesystem/Rust tests and actual OS picker/capacity are CI/device-only here.

Per-model requested context is a saved preferences map keyed by exact tag. Blank inherits global/daemon default. It is not model maximum or measured capacity. Settings draft only affects future runs after Save; saved Agent provider selects the exact model override (including studio request model). Native preferences validate bounds. Existing generic global behavior stays backward compatible. Dedicated vision/probe adapters using explicit option objects are not silently retargeted.

Progress remains per-layer, never fake overall percent; completion still requires terminal success plus fresh inventory and locality verification. Delete remains explicit and blocked for saved active/studio model assignments. No automatic replacement or secure-erasure claim. New presentation uses DS Button/Input/Checkbox/Dialog/StudioStatus, not custom controls.

# Project file tree disclosure and keyboard navigation

The Files panel previously rendered directories as static labels. Folder rows are now disclosure buttons, using the existing DS Button, icon set and 32px virtualized layout. Enter/Space or a click toggles a folder. `aria-expanded` reports its state; the accessible label includes the full path in all five locales. The existing file and folder action buttons remain independent controls. This is a navigation/disclosure list, not a claim of a complete ARIA tree widget or single-tab-stop roving tree.

On a file/folder navigation button, Up/Down move through visible rows, Home/End move to the first/last visible row, Right opens a collapsed folder or focuses its first child, and Left closes an open folder or focuses its parent. No selection/file mutation happens on arrow navigation. Enter on a file still opens it. The virtualizer keeps the focused row mounted and uses data attributes rather than interpolating paths into CSS selectors.

Collapsed descendants are filtered by exact path segments. Closing `src/a` never hides `src/ab`; nested collapsed choices survive closing/reopening their parent. An active-file change from tabs, search, Quick Open or new-file creation discloses its ancestors. Users can still collapse the currently active file's ancestor; it is not immediately reopened on unrelated renders. Reopening the same already-active path without an active-file change does not force disclosure. Disclosure is local to this panel mount, resets on project generation changes and is not a persistent workspace preference.

Existing create/duplicate/rename/delete operations and editor-core undo are unchanged. Disclosure itself does not enter source history, save files, read the filesystem or modify project contents. The Files host is shared with Documents, so the same navigation improvement applies there. No new dependency, toolbar area, command registration, sorting rule or native behavior is introduced.

Focused verification covers nested/prefix paths, non-mutating reveal, keyboard destinations and 5,000-file filtering; real browser cases cover Light/Dark, folder toggles, keyboard/focus, external reveal, creation into hidden ancestors, duplicate/collision validation, folder rename/delete/owner undo, project switching and 1,000-file virtualization. Native/WASM and packaged desktop remain CI-only.

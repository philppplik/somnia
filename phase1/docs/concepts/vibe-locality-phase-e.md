# Vibe daemon-locality phase E

Native Vibe now requests fresh `/api/show` metadata for the saved exact Ollama model immediately before every inference request, including later tool steps, scheduled runs and request-changes. This applies even with local-only off because Vibe's local label must not bypass cloud disclosure policy. The request host never accepts a renderer-supplied evidence bit. The metadata path is numeric loopback, with proxies and redirects off, bounded response bytes and a timeout. Only a nonempty object `model_info` with no non-null `remote_host` / `remote_model` marker and no cloud suffix is accepted. Empty, malformed, unavailable and unknown evidence deny inference. Local-only can now allow verified Ollama while still denying cloud and unknown LM Studio; previously resolved transports recheck evidence on their next request. No automatic download, no new dependency.

Evidence means daemon-reported local weights, not cryptographic proof or an audit of a user-managed daemon. A malicious daemon can lie, and external changes between metadata and inference cannot be made atomic over the daemon API. Somnia does not promise a system firewall. Native cloud request guards still cancel owned operations when local-only changes; already-sent bytes cannot be recalled. LM Studio stays unknown in local-only until an equivalent weight-locality contract is supported.

The selected local-model health panel shows daemon reachability, inventory count, exact selected model locality and the last check's fixed error. Refresh is read-only and manual after the initial check. No prompt is used, no inference occurs, no raw daemon errors are shown. UI checks are guidance, never authorization: native Vibe checks again at request time. Listed model readiness elsewhere remains inventory/trial guidance, not this locality evidence. New Studio's selected local model shows this panel; it does not hide a configured model or invent a cloud fallback.

# Local assistant context, templates and routing explanation

Local Agent runs offer an explicit context checklist: active document/media plus its tools, selection, studio metadata, custom instructions and prior chat history. Excluding the document clears active file/media, removes document tools and scrubs document/selection references in studio metadata before any snapshot/provider work. Excluding selection clears node/range and selection summary. Excluding studio also removes its per-studio model override. Custom instructions are omitted from provider construction. History is off by default; context-choice identity changes prevent replay from a previous source scope. No hidden cloud fallback: controls require Ollama at execution and general routing is disabled for these local scoped runs. Existing cloud runs retain their existing explicit consent path and do not receive this local context mode.

Budget rows are estimates of prompt, bounded document, enabled instructions and studio metadata. UTF-8 bytes divided by four is not a tokenizer or context fit promise. System/tool schemas, retained history, media and later tool results are explicitly outside the estimate; media/history size unknown. Document bytes limit rejects oversized input, never silently truncates or misrepresents a whole file. Tool results remain native permission/context guarded; this panel is not a hard total context/token cap. Native/media snapshot representation may differ from visible text preview. User can deselect source categories and lower document bytes before sending.

Why this model uses actual precedence: task default, then saved studio default if studio included and provider local, then global provider/model. Explains configuration, not quality. The Agent status uses the same effective model; no prompt-word task guessing.

Templates live in bounded local JSON storage: 24 records, 4000 characters each, 200 KB cap, task key chat/vibe/code/summarize. Task selection in template manager is explicit. Edit/save is separate from Use as draft; use replaces prompt text and does not send, choose a model, mutate project or grant tools. Each template can be deleted. No external sync or cloud store. Existing Vibe creation remains unchanged: Vibe templates can be authored here and used as editable draft text, not silently sent to a Studio.
